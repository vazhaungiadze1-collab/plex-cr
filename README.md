# PLEX — კონკურენტების USD/USDT კურსების დეშბორდი

დღიურად (ავტომატურად) კრეფს Werty, GeCrypto, Alltrust, Bitcasa, Gaus Crypto და Stellex-ის ვებგვერდებიდან USD ⇄ USDT კურსებს და აჩვენებს მარტივ, გუნდისთვის დაცულ დეშბორდზე Firebase Hosting-ზე.

## რაზეა აგებული

**სრულიად უფასოდ მუშაობს — Firebase-ის ფასიან (Blaze) გეგმაზე გადასვლა არ არის საჭირო.** სქრეიფინგი (გარე საიტების გამოძახება) კეთდება Firebase Cloud Functions-ის ნაცვლად **GitHub Actions**-ზე — ეს არის GitHub-ის საკუთარი, სრულიად უფასო "დაგეგმილი გაშვების" სერვისი, რომელიც უბრალო Linux მანქანაზე უშვებს იმავე კოდს, სრული ინტერნეტ-წვდომით, ბარათის მიბმის გარეშე.

- **GitHub Actions (`scripts/update-rates.js` + `.github/workflows/update-rates.yml`)** — დღეში სამჯერ (09:00, 15:00, 21:00 საქართველოს დროით) გაეშვება ავტომატურად, დაუკავშირდება თითოეული კომპანიის საიტის იმავე შიდა API-ს, რომელსაც მათი საკუთარი კალკულატორი იყენებს, და ჩაწერს Firestore-ში (`rates/{company}` + `rates/{company}/history/{თარიღი}`). თითოეული მოთხოვნა 3-ჯერ იმეორებს (retry) წამოკითხვის შეცდომაზე, სანამ საბოლოოდ ჩავარდნილად ჩაითვლება.
- **Firestore (Spark/უფასო გეგმა)** — ინახავს ბოლო კურსებს და ისტორიას, ასევე ზედიზედ ჩავარდნების რაოდენობას (`consecutiveFailures`). GitHub Actions წერს იქ სერვის-ექაუნთის (service account) გასაღებით.
- **Firebase Hosting (`public/index.html`, Spark/უფასო გეგმა)** — მარტივი დეშბორდი Google-ით შესვლით (ინგლისურენოვანი); მონაცემებს კითხულობს პირდაპირ Firestore-დან რეალურ დროში.
- **Firestore Security Rules** — მონაცემების წაკითხვა შესაძლებელია **მხოლოდ `@plex-team.com` დომენის Google ანგარიშებისთვის** — შემოწმება ხდება სერვერის მხარეს, Firestore-ის წესებში, ასე რომ დეშბორდის მისამართის ცოდნა საკმარისი არაა წვდომისთვის. ნებისმიერი username მუშაობს, სანამ ბოლოვდება `@plex-team.com`-ით — არც ერთი კონკრეტული ელფოსტა არაა hardcoded.
- **Analytics tab** — რამდენჯერ და რამდენით შეიცვალა თითოეული კომპანიის კურსი (7/30 დღის ჭრილში), საუკეთესო კურსის ლიდერბორდი, და ავტომატური ყოველკვირეული რეპორტი.
- **PLEX Calculator tab** — შეიყვანეთ საკუთარი კურსები, ავტომატურად შედარდება ყველა კონკურენტთან, პროცენტულად.

## ⚠️ მნიშვნელოვანი შეზღუდვა

ეს **არ არის** ოფიციალური საჯარო API — თითოეული საიტის კალკულატორის შიდა endpoint-ია, რომელიც ნებისმიერ დროს, გაფრთხილების გარეშე შეიძლება შეიცვალოს ან დაიბლოკოს. ამიტომ:

- ყოველი კომპანიის fetch-ი ცალკეა try/catch-ში — ერთის გაფუჭება არ აჩერებს დანარჩენებს.
- ყოველი მოთხოვნა თავად იმეორებს 3-ჯერ (500მწმ, შემდეგ 2წმ დაყოვნებით) მანამ, სანამ საბოლოოდ შეცდომად ჩაითვლება — ერთჯერადი ქსელური "ციმციმი" არ გაანულებს დღის მონაცემს.
- განახლება დღეში სამჯერ ხდება (09:00, 15:00, 21:00), ასე რომ ერთი გაშვების ჩავარდნაც კი იმავე დღეს კიდევ ორჯერ გამოსწორდება ავტომატურად.
- დეშბორდი განასხვავებს სამ მდგომარეობას: **Live** (ბოლო 20 საათში წარმატებით განახლდა), **Stale** — მოძველებული (20 საათზე მეტია განახლების გარეშე, ანუ დღევანდელი სამივე მცდელობა ჩავარდა) და **Error** (ბოლო მცდელობა უშუალოდ ჩავარდა — ნაჩვენებია ბოლო ცნობილი კურსი + შეცდომის ტექსტი + რამდენჯერ ზედიზედ).
- **Stellex**-ს არ აქვს გამოქვეყნებული ფიქსირებული USD/USDT კურსი — მხოლოდ საკომისიოს საფეხურები საბაზრო კურსზე დამატებით. ამიტომ მისი ბარათი აჩვენებს საკომისიოს ცხრილს რიცხვების ნაცვლად (და არ ერგება Stale/Live ლოგიკას).
- დროდადრო საჭირო იქნება route ID-ების ხელახლა გადამოწმება (`scripts/lib.js`-ში), თუ რომელიმე საიტი მთლიანად შეცვლის კალკულატორს.

## წინაპირობები

1. Firebase პროექტი — **Spark (უფასო) გეგმა საკმარისია, Blaze-ზე გადასვლა არ არის საჭირო.** სქრეიფინგი ხდება GitHub Actions-ზე (იხ. ქვემოთ), არა Firebase Cloud Functions-ზე — ამიტომაა, რომ ფასიანი გეგმა საერთოდ არ გვჭირდება.
2. Firebase CLI დაყენებული და დალოგინებული (`firebase login`).
3. Firebase Authentication-ში ჩართული **Google** sign-in მეთოდი (Console → Authentication → Sign-in method → Google → Enable).
4. **უფასო GitHub ანგარიში** — თუ არ გაქვთ, შექმენით [github.com](https://github.com)-ზე (30 წამის საქმეა, ბარათი არ სჭირდება).

## დაყენება

```bash
cd plex-rates-dashboard

# დააკავშირე შენს არსებულ Firebase პროექტთან
firebase use --add
# ჩამოთვლილიდან აირჩიე შენი PLEX-ის პროექტი

# შექმენი დასახელებული Hosting საიტი (იხ. "ბმულის სახელი" ქვემოთ) — ერთხელ, პირველ დეპლოამდე
firebase hosting:sites:create plex-cr

# გამართვები + ჰოსტინგი (ფუნქციები აღარ გვჭირდება)
firebase deploy --only firestore,hosting
```

დეპლოის შემდეგ ტერმინალი დაგიბეჭდავს ჰოსტინგის ბმულს — `https://plex-cr.web.app` (და `https://plex-cr.firebaseapp.com`) — ეს არის დეშბორდის ბმული, გაუზიარე გუნდს.

**ცალკე ნაბიჯად** საჭიროა GitHub-ის მხარეს რეპოზიტორის შექმნა და `FIREBASE_SERVICE_ACCOUNT` საიდუმლოს (secret) დამატება, რომ `scripts/`-ში კოდმა შეძლოს Firestore-ში ჩაწერა — დაწვრილებით იხილეთ `PLEX-Firebase-Deploy-Guide.md`.

## ბმულის სახელი ("plex.cr")

ითხოვეთ, რომ ბმულს წინ ჰქონდეს "plex.cr" და მერე Firebase-ის უფასო მისამართი. ტექნიკური დეტალი, რაც ღირს ცოდნა: Firebase Hosting-ის უფასო მისამართი ყოველთვის არის ფორმის `<site-id>.web.app`, და `<site-id>`-ში **წერტილი (.) დაშვებული არაა** — მხოლოდ პატარა ასოები, ციფრები და დეფისი. ანუ ზუსტად "plex.cr.web.app" ვერ გამოვა.

ამიტომ ამ პროექტში `firebase.json`-ში Hosting საიტის სახელად დაყენებულია **`plex-cr`** (წერტილის ნაცვლად დეფისი) — უახლოესი ვარიანტი თქვენს მოთხოვნასთან. საბოლოო ბმული იქნება:

```
https://plex-cr.web.app
```

**მნიშვნელოვანი:** Site ID გლობალურად უნიკალურია ყველა Firebase პროექტს შორის (როგორც დომენი) — თუ `plex-cr` უკვე დაკავებულია ვინმეს მიერ, `firebase hosting:sites:create plex-cr` შეცდომას დააბრუნებს. ასეთ შემთხვევაში სცადეთ მსგავსი ვარიანტი (მაგ. `plex-crypto`, `plex-rates`, `plexcr`) და იგივე სახელი ჩაწერეთ `firebase.json`-ის `hosting.site` ველშიც. თუ გნებავთ ნამდვილი "plex.cr" დომენი (მაგ. საკუთარი დომენის შეძენით), ეს უკვე Custom Domain-ის საკითხია — მითხარით, გაგიწევთ ინსტრუქციას.

## წვდომა — მხოლოდ @plex-team.com

წვდომა შეზღუდულია დომენით, ინდივიდუალური სიის ნაცვლად: `firestore.rules`-ში წესი უშვებს წაკითხვას მხოლოდ იმ Google ანგარიშისთვის, რომლის ელფოსტაც მთავრდება `@plex-team.com`-ით (`request.auth.token.email.matches('.*@plex-team[.]com$')`). ეს ნიშნავს:

- ნებისმიერს, ვისაც `@plex-team.com` Google Workspace ანგარიში აქვს, ავტომატურად შეუძლია შესვლა — არაფრის დამატება არ სჭირდება Firestore-ში.
- ვინც სხვა დომენით/პირადი Gmail-ით შეეცდება შესვლას, დეშბორდი მაშინვე გამოაგდებს ("This dashboard is restricted to @plex-team.com accounts") — ეს არის მხოლოდ მოხერხებულობისთვის კლიენტის მხარეს; რეალური დაცვა Firestore rules-შია, სერვერის მხარეს.

## განრიგის შეცვლა

`.github/workflows/update-rates.yml`-ში:

```yaml
on:
  schedule:
    - cron: "0 5,11,17 * * *"   # UTC-ში! Asia/Tbilisi 09:00/15:00/21:00-ის შესატყვისი
```

ნაგულისხმევად დღეში 3-ჯერ განახლდება. თუ გნებავთ ხშირად ან იშვიათად, შეცვალეთ cron გამოსახულება (მაგ. `"0 */6 * * *"` = ყოველ 6 საათში, `"0 5 * * *"` = მხოლოდ დღეში ერთხელ). **გაითვალისწინეთ: GitHub Actions-ის cron ყოველთვის UTC დროზეა** — საქართველოს დრო (Asia/Tbilisi) UTC+4-ია, ზამთარ-ზაფხულის დროზე გადასვლის გარეშე, ასე რომ საკმარისია 4 საათის გამოკლება. დეშბორდის `STALE_AFTER_HOURS` მნიშვნელობაც (`public/index.html`) შესაბამისად უნდა მოირგოთ, თუ სიხშირეს შეცვლით.
